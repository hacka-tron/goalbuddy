How to build Buildpair from scratch

A design for a new repository that ignores the GoalBuddy code. It is tuned for a chat-first product, 1,000 daily users at the start, free tiers wherever they exist, low latency everywhere, and a production-grade release pipeline. Prices and versions were checked on the date above.

The decision

  • One Expo app (React Native, Expo SDK 57) for iOS, Android and the web, with desktop layouts inside the same app.
  • Cloudflare for everything server-side. Workers run the API. Each space is a Durable Object that owns that space's list and chat. Each person has one for their inbox and reminders. D1 holds global data, R2 holds files, and Queues and Workflows run background jobs.
  • SQLite everywhere. Inside each space's Durable Object (the space's source of truth), in D1 (managed SQLite for global data), and on each device (the local copy that makes the app instant and work offline).
  • TypeScript end to end. One shared package of domain rules runs on the device for instant updates and on the server for the real ones.
  • GitHub Actions and EAS for CI/CD: a preview environment per pull request, staging on merge, approved production releases with gradual rollout and one-command rollback.
$5–40a month at 1,000 daily users, plus Apple's $99 a year. Details in Cost.

The product's unit of everything is the space: a list plus one chat, shared with a few people. The architecture uses the same unit. Each space becomes a small, strongly consistent database that also runs the space's live connections, placed near its members.

How a message travels

Chat is the core of the product, so this is the path the architecture is built around. Maya sends a message in her Life space; Jordan has the space open on his laptop; Kim's phone is in her pocket.

Where data lives

On each device

A local copy of every space the person is in, plus a queue of changes not yet confirmed. Today, Upcoming and search across your own spaces are local queries.

SpaceRoom (one per space)

Members and roles, purpose, items and schedules, done and skip history with reasons, messages, reactions, read positions, and the numbered event log.

UserHub (one per person)

Their spaces with unread counts, devices and push tokens, Activity inbox, and a personal agenda so reminders and summaries fire from one place.

D1 (global)

Accounts and sessions, usernames and Buildpair IDs, invite links, Discover listings and offers, integration connections, blocks and reports.

R2

Avatars, attachments, nightly exports for analytics and disaster recovery.

Rules that keep Durable Objects cheap and correct: use the Hibernation WebSocket API and alarms (never in-memory timers) so idle rooms aren't billed; store each room's schema version and migrate on wake; create each space with a location hint near its owner.

The sync protocol

The app never waits on the network to update the screen. Every change is a command; the server answers with numbered events.

  1. The app gives the command its own ID, applies it to the local copy immediately with the shared domain code, and saves it in a pending queue that survives restarts.
  2. The space's room checks membership and permissions, applies the command with the same domain code, appends events with the next numbers, and remembers the command ID so retries are harmless.
  3. The room sends the events to devices with the space open and pokes each member's UserHub, which tells that person's other devices.
  4. Devices apply events in order and drop the matching pending command. A rejected command is rolled back with a clear message.
  5. After a reconnect, a device asks for everything after its last number; one that has been away too long gets a snapshot.

Events about "only visible to me" items go only to their owner. Commands and events are versioned Zod schemas in a shared protocol package, so older app versions keep working while new ones roll out.

What makes the chat seamless

  • Opens instantly from the last 50 messages stored on the device.
  • Sends instantly: shown as pending, queued while offline, never duplicated.
  • Never out of order or missing: one numbered sequence per space; a gap triggers a fetch.
  • Presence and typing over the open space's socket, throttled and never stored.
  • Push only when it helps: none if you're active in that space on any device; grouped ("Alex and 4 others reacted 🔥").
  • Completions, skips, rolled-up to-dos and update notes are written by the room into the same log, so the list and the chat can't disagree.
  • Phone keyboard and scrolling handled properly (react-native-keyboard-controller, a list anchored to the newest message).
  • Attachments upload straight to R2 with a signed URL.

Reminders, notifications and Discover

  • Each UserHub sets one alarm for the person's next due thing: a reminder, the morning summary, the weekly review prompt.
  • Each SpaceRoom sets alarms for its own checks: a goal gone quiet (nudges go to supporters only), weekly summary lines, offer expiry.
  • Alarms put jobs on a Queue; the Notifier picks phone push, browser push or email, and applies quiet hours and grouping.
  • With "Show on Discover" on, the room writes a listing to D1 (purpose, goal summaries, time zone, wants, top badge; locked items never). "For you" starts as ranked SQL; embeddings can come later.

Integrations, the next big feature

  • An Integrations Worker runs the OAuth connect flows (Jira first, then Linear and GitHub) and stores tokens encrypted in D1.
  • Webhooks are verified, queued, and handled by a Workflow (durable, with retries) that turns an outside event into a normal command for the right space. A ticket closed in Jira becomes an item marked done and a chat line.
  • Each tool is an adapter behind one interface; cron-driven polling covers tools without webhooks. Supporters see goal progress, never the backlog.
  • Habit sources (Apple Health, Health Connect, Strava) fit the same shape; Apple Health data is read on the device and sent as commands.

The app

  • One Expo app with Expo Router. Routes are real URLs on the web (buildpair.app/spaces/life) and deep links on phones.
  • Desktop layouts live in web-only files in the same app: sidebar, margin, popovers, right-click menus, shortcuts, Cmd+K. If React Native Web ever limits the desktop experience, the shared packages make a separate React DOM web app a contained project.
  • State: synced data in the sync store, screen-only state in small Zustand stores, one-off requests (Discover search, profiles) through TanStack Query.
  • Libraries: Reanimated 4, FlashList v2 or Legend List (spike both for the chat view), expo-image, expo-notifications, expo-secure-store, react-native-keyboard-controller, chrono-node for "dentist friday 3pm", rrule for repeats, a Temporal polyfill for time zones.
  • Sign-in and store rules: offering Google on iOS means offering Sign in with Apple too; user content needs report and block; accounts must be deletable inside the app (a Workflow removes the person from D1, every room and R2).
  • Landing page: a separate static Astro site on Cloudflare.

The domain package is the key to correctness: the same code applies a change on the device and in the room, so the two can't drift apart.

CI/CD

Tools: pnpm and Turborepo, Biome, TypeScript project references, Vitest (Workers and Durable Objects tested in the real runtime with @cloudflare/vitest-pool-workers), Playwright for the web, Maestro for phone flows, Changesets, Renovate, gitleaks.

  • Protected main, required checks, CODEOWNERS, previews torn down when a PR closes, secrets only in GitHub Environments and Cloudflare.
  • iOS builds run on EAS, not GitHub's macOS runners, which keeps Actions within the free minutes.
  • Approval gates on GitHub Environments are free on public repositories; private ones need a paid GitHub plan for required reviewers.
  • Operations: D1 Time Travel and Durable Object point-in-time recovery (30 days), nightly exports to R2, Sentry alerts, billing alerts as a guard on Durable Object costs, a feature flag on every risky feature.

Build order

  1. Foundations (week 1): repo, CI with previews, environments, sign-in, a hello-world space on iOS, Android and web.
  2. Spaces and chat: SpaceRoom, UserHub, the sync protocol, chat with reactions, the offline queue and push. The riskiest part goes first.
  3. Items: to-dos, habits, goals, schedules, natural-language adding, Today, reminders.
  4. People: invites, roles, Activity, Supporting, quiet-goal nudges.
  5. Discover: listings, offers, requests, profiles, badges, compliments.
  6. Desktop extras and beta: Cmd+K, Upcoming, weekly review, polish.
  7. Integrations: Jira first.
